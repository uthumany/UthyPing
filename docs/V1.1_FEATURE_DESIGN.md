# UthyPing Version 1.1 feature design

## Scope

Version 1.1 improves two existing surfaces without changing the network-monitoring model or the visual identity:

1. **Panel indicator customization** — let users choose what the GNOME top-panel indicator communicates.
2. **Configurable display modes** — make the existing Mini, Compact, and Expanded layouts explicit, predictable, and easy to switch.

The current code already has the three layout modes in `WidgetController` and the `display-mode` GSettings key. Version 1.1 should refine that contract rather than add a second layout system.

## Design principles

- Keep the default experience unchanged for existing users.
- Use explicit enums rather than free-form strings.
- Keep all settings local; no telemetry or remote service is introduced.
- Preserve square corners, the dark instrument-panel material, orange active accent, and reduced-motion guarantees.
- A user must be able to understand the selected mode and panel content without relying on color alone.
- Settings changes apply immediately; no restart should be required.
- The panel indicator must remain useful at small panel sizes and must not cause excessive width changes on every sample.

## Feature A: panel indicator customization

### User-facing settings

Add a new **Panel indicator** group in Preferences:

| Setting | Type | Default | Options |
|---|---|---|---|
| Panel indicator | enum string | `icon` | `icon`, `download`, `upload`, `combined`, `status` |
| Show panel indicator | boolean | `true` | On / Off |

The existing panel menu remains available when the indicator is visible. If the user disables the indicator, UthyPing removes the status-area button but the widget and keyboard/prefs access continue to work.

### Indicator modes

#### Icon only — `icon`

Current default behaviour:

```text
[UthyPing icon]
```

Accessible name:

```text
UthyPing network monitor
```

#### Download — `download`

```text
↓ 12.4 MB/s
```

Uses the bundled download icon and the current download rate. The icon remains visible when the rate is unavailable; the text displays `—` during initialization.

#### Upload — `upload`

```text
↑ 1.8 MB/s
```

Uses the bundled upload icon and the current upload rate.

#### Combined — `combined`

```text
↓ 12.4 MB/s  ↑ 1.8 MB/s
```

This is the most informative mode but can become wide. The indicator should use a fixed compact width per font scale and tabular numerals so normal sampling does not move neighbouring panel items.

#### Status — `status`

```text
● eth0
```

Shows the connection LED state plus the active interface name. The accessible name must include the state in words, for example `UthyPing connected on eth0`, not only the color or dot.

### Formatting rules

- Reuse the existing byte-rate formatter used by the widget; do not create a second unit-conversion implementation.
- Use decimal units consistently: `B/s`, `KB/s`, `MB/s`, and `GB/s`.
- Use tabular numerals.
- During initialization, show `—` rather than `0.0`.
- When paused, retain the latest reading and add the accessible state `paused`; do not replace the value with zero.
- When disconnected, show `—` and expose `disconnected` in the accessible name.
- Truncate only interface names in `status` mode, and preserve the full name in the accessible label.

### Panel lifecycle

The indicator should be owned by a small `PanelIndicatorController` or equivalent helper in `extension.js`:

- Create the panel button only when `show-panel-indicator` is true.
- Rebuild its child content when `panel-indicator-mode` changes.
- Update text/icon content on monitor updates without recreating the panel button.
- Destroy the button and disconnect settings signals in `disable()`.
- Keep the existing menu actions: show/hide widget, pause/resume, reset statistics, and preferences.
- If the indicator is hidden, the settings remain accessible from the widget's Preferences control.

### Accessibility

Each mode has a full dynamic accessible name:

- `UthyPing network monitor`
- `UthyPing download 12.4 megabytes per second`
- `UthyPing upload 1.8 megabytes per second`
- `UthyPing download 12.4 megabytes per second, upload 1.8 megabytes per second`
- `UthyPing connected on eth0`

Do not announce every sampling update through a screen reader. State changes worth announcing are limited to connection transitions, pause/resume, and interface changes.

## Feature B: configurable display modes

### Existing modes, clarified

The existing `display-mode` key remains the source of truth:

| Mode | Size preset | Intended use | Content |
|---|---:|---|---|
| `mini` | 280 × 136 | Always-on glance | Header, download/upload readings, small graph, interface status |
| `compact` | 340 × 164 | Small desktop monitor | Mini content with more room for values and graph |
| `expanded` | 500 × 310 | Investigation | Metric wells, graph window, statistic slots, status, floating controls |

The current user-resized dimensions should continue to be respected within each mode's minimum size. Selecting a mode applies its preset only when the mode changes; it must not continually overwrite user geometry.

### Preferences behaviour

Keep the existing **Display mode** combo row, but make its copy explicit:

- **Mini** — “Small always-on readings and status.”
- **Compact** — “More room for values while preserving a low footprint.”
- **Expanded** — “Full graph, session statistics, and control tray.”

When a user changes the mode:

1. Save the enum immediately.
2. Apply the mode-specific minimum/preset geometry.
3. Re-render the content without restarting the extension.
4. Preserve the widget's top-left anchor where possible.
5. Clamp the result to the active monitor.
6. Keep the selected interface, colors, graph setting, and position settings unchanged.

### Quick mode switching

Add a **Cycle display mode** action to the widget's accessible interaction model and panel menu. The cycle order is:

```text
Mini → Compact → Expanded → Mini
```

The action should be available from:

- The panel menu.
- A keyboard-accessible control in the widget or its menu, but not as a new permanent visual button in Mini mode.

The existing header expand/minimize controls remain for direct navigation. Their semantics should be:

- Mini: expand control opens Expanded.
- Compact: expand control opens Expanded.
- Expanded: expand control moves to Compact.
- Minimize: temporarily reduces the current mode to Mini without changing the saved `display-mode` preference.

This preserves the current distinction between a saved default mode and a temporary minimized state.

### Mode-specific accessibility

The widget accessible name should include the current mode:

```text
UthyPing network monitor, expanded layout
```

When the mode changes, expose one state update rather than announcing every child replacement. Keyboard focus must return to the widget root or the equivalent logical control after re-rendering; focus must not disappear because the old layout actors were destroyed.

### Reduced motion

Mode changes must not animate layout movement when Reduce motion is enabled. With motion enabled, a future transition may fade or translate the content, but Version 1.1 should prefer a simple immediate replacement to avoid introducing layout-jank and focus bugs.

## Proposed schema additions

Keep the existing schema ID and path for settings compatibility. Add:

```xml
<key name="show-panel-indicator" type="b"><default>true</default></key>
<key name="panel-indicator-mode" type="s"><default>'icon'</default></key>
```

Do not rename `display-mode`; it already provides the correct stable setting.

Recommended validation constants in `SettingsManager`:

```js
const VALID_PANEL_INDICATORS = ['icon', 'download', 'upload', 'combined', 'status'];
```

Invalid values fall back to `icon` without writing to settings during runtime.

## Preferences layout

Place a new **Panel indicator** group between Monitoring and Appearance:

1. `Show panel indicator` — switch.
2. `Panel indicator content` — combo row, disabled when the switch is off.
3. `Display mode` — remain in Monitoring, because it changes the primary widget layout.

The combo labels should be human-readable:

- Icon only
- Download speed
- Upload speed
- Download + upload
- Connection status

The subtitle should explain that panel updates are local and use the same readings as the widget.

## Implementation sequence

### Phase 1: settings and formatting

1. Add the two schema keys.
2. Add `SettingsManager.panelIndicatorMode` and `showPanelIndicator`.
3. Extract or reuse the existing byte-rate formatter for panel text.
4. Add unit tests for enum fallback and all indicator formatting states.

### Phase 2: panel indicator controller

1. Split indicator creation/update/menu code out of the extension class or keep it behind clearly separated methods.
2. Add one stable panel button actor.
3. Add mode-specific icon/text children.
4. Update content from `NetworkMonitor` data without recreating the button.
5. Handle visibility and mode settings changes.
6. Preserve accessible names and menu actions.

### Phase 3: preferences

1. Add the Panel indicator group.
2. Bind the visibility switch.
3. Add the mode combo row.
4. Disable the mode row when the indicator is hidden.
5. Verify keyboard navigation and high-contrast readability.

### Phase 4: display-mode polish

1. Update display-mode subtitles and accessible names.
2. Add “Cycle display mode” to the panel menu.
3. Preserve focus and geometry during re-render.
4. Add tests for temporary minimize versus saved display mode.

### Phase 5: runtime and packaging verification

1. Validate schemas and JavaScript syntax.
2. Run unit tests for settings, formatter, mode transitions, and indicator states.
3. Run nested GNOME Shell tests for every panel mode.
4. Capture Mini, Compact, and Expanded screenshots with icon-only and combined indicators.
5. Test disabling/re-enabling the panel indicator.
6. Test reduced motion and keyboard focus after mode changes.
7. Build both install and source archives.
8. Commit the work in logical GNOME-style commits and publish through GitHub Actions.

## Acceptance criteria

- Existing users keep the current icon-only panel indicator and Mini default with no settings migration prompt.
- Every panel mode updates from live monitor data without recreating the panel button.
- No panel mode displays `0.0` during initialization when a value is unknown.
- The combined indicator remains visually stable while values change.
- Hiding the panel indicator removes only the panel button, not monitoring or the widget.
- Changing display mode applies immediately and preserves the selected interface and appearance settings.
- Temporary minimize does not overwrite the saved display mode.
- Focus and accessible names remain valid after every mode change.
- Reduced motion prevents any mode-transition easing and control animation.
- No Shell warnings, GJS criticals, TypeErrors, or unbounded timers occur during repeated mode/indicator changes.
- Install and source archives contain only the new `uthyping` identifiers.

## Deliberately deferred from Version 1.1

- Latency, packet loss, jitter, and quality scoring.
- Daily/weekly persistent traffic totals.
- Process-level bandwidth attribution.
- User-defined panel text templates.
- Multiple simultaneous panel indicators.
- Animated transitions between display modes.
